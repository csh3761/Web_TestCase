# 테스트 하네스 구조 및 기능 테스트 케이스

## 1. 개요

이 문서는 프로젝트를 **테스트 하네스(Test Harness)** 관점으로 구조화하고, 각 기능 항목(모듈)별 **기능 테스트 케이스**를 정리한 문서다.

테스트 하네스는 아래 4가지 요소로 구성된다.

| 하네스 구성요소 | 역할 | 이 프로젝트의 매핑 |
|---|---|---|
| Test Driver | 테스트 대상을 호출하고 실행을 제어 | `HYNIX/*.py`의 `main()` / `run()` (argparse 기반 CLI 진입점) |
| Test Data / Fixture | 입력값, 계정, 환경 설정 | `csv/업로드목록.csv`, `config/*.json`, `config/password.txt` |
| Stub / Driver 대상(SUT) | 실제 테스트 대상 시스템 | OTCS 계열 사내 웹 문서관리시스템 (Playwright로 원격 조작) |
| Oracle / 비교 기준 | 성공/실패 판정 근거 | `status` 문자열, HTTP status code, `check_session` 응답, 로컬 파일시스템 스캔 결과 |
| Log & Report | 실행 결과 기록 | `reports/*.json`(결과), `reports/*.log`(진행 로그), `reports/*.png`(스크린샷) |

### 1.1 모듈 계층 구조

```text
HYNIX/login_session_check.py   ─┐  (핵심 공용 라이브러리: Account, 로그인, 세션, 폴더 탐색, 업로드 API, 로그아웃)
HYNIX/explorer_path_test.py    ─┤  (공용 라이브러리 겸 단독 실행: CSV 로딩, 로컬 파일 스캔, Windows 탐색기 COM 제어)
                               │
        ┌──────────────────────┼───────────────────────────────────────────┐
        ↓                      ↓                                           ↓
connection_test_first_user.py  user_upload_test.py ──→ main_test_user3.py  user_auto_login.py
(연결/로그인 스모크 테스트)      (사용자 1명 업로드)      (부서별 N명 배치 업로드)  (고정 계정 자동 로그인 + EXE 빌드)

Main_Report.py                sys_trash.py ──→ user_trash.py
(전체 계정 업로드 결과 검증)     (관리자 휴지통 정리, Sys Trash)  (사용자 휴지통 정리)

probe_login_dom.py, probe_otcs_login_dom.py
(로그인 폼 DOM 구조 탐색 - 디버깅 전용 도구, 정식 테스트케이스 아님)
```

### 1.2 테스트 케이스 ID 규칙

`{항목코드}-{일련번호}` 형식을 사용한다. (예: `LOGIN-01`)

| 코드 | 기능 항목 |
|---|---|
| `LOGIN` | 로그인/인증 |
| `SESSION` | 세션 검증 |
| `NAV` | 문서함 내비게이션 (folderId 확정) |
| `EXPLR` | 로컬 파일 탐색 (CSV 기반 + Windows 탐색기 COM) |
| `UPLOAD` | 업로드 (생성→청크→완료→가시성 검증) |
| `VERIFY` | 업로드 결과 검증/리포트 (Main_Report) |
| `TRASH-U` | 사용자 휴지통 정리 |
| `TRASH-A` | 관리자 휴지통 정리 |
| `LOGOUT` | 로그아웃 |
| `BATCH` | 다중 계정/배치 실행 |
| `BUILD` | 고정 계정 EXE 빌드 |
| `PROBE` | DOM 프로브(디버깅 도구) |

## 2. LOGIN — 로그인/인증

관련 파일: `HYNIX/login_session_check.py`(핵심 로직), `HYNIX/connection_test_first_user.py`(단독 스모크 테스트)

| TC ID | 기능 항목 | 사전조건 | 절차 요약 | 기대 결과 (판정 기준) |
|---|---|---|---|---|
| LOGIN-01 | 정상 계정 로그인 성공 | CSV/`config/login_config.json`/`password.txt` 정상 | `login_url` 접속 → ID/PW 입력 → 제출 | `login_response_status` = `LOGIN_RESPONSE:2xx`, `main_frame_url`에 `/login/loginSuccess` 포함 |
| LOGIN-02 | 로그인 응답 캡처 실패해도 후속 진행 | 네트워크 지연으로 POST 응답을 8초 내 못 잡음 | 제출 후 `submitOk()` JS 폴백 또는 Enter 키 폴백 실행 | `LOGIN_RESPONSE_NOT_CAPTURED`여도 `main_frame_url`이 `/login/loginSuccess`로 전환되면 계속 진행 |
| LOGIN-03 | 로그인 후 UI 미출현 | 사이드바/워크박스 셀렉터가 실제 DOM과 불일치 | `wait_after_login` 8초 대기 | `RuntimeError("로그인 후 문서함 UI를 찾지 못했습니다.")` 발생, `status="FAILED"` |
| LOGIN-04 | 인증 세션 준비 타임아웃 | 로그인 직후 `/documents` API가 계속 비정상 응답 | `wait_for_authenticated_session` 20회(200ms 간격) 재시도 | `RuntimeError("로그인 세션 API가 준비되지 않았습니다. last_status=...")` |
| LOGIN-05 | 이미 로그인된 세션 재진입 | 쿠키/세션이 이미 `/login/loginSuccess` 상태 | `login_otcs` 진입 시 프레임 URL 즉시 확인 | `login_response_status="ALREADY_LOGGED_IN"` |
| LOGIN-06 | CSV 필수 컬럼 누락 | CSV에 `성명`/`사용자ID`/`부서 경로` 중 하나라도 없음 | `load_first_accounts` 호출 | `ValueError("CSV 필수 컬럼이 없습니다: ...")` |
| LOGIN-07 | 공통 비밀번호 미설정 | 환경변수 `DOCSPHERE_PASSWORD` 없음 + `password.txt` 없음 | `get_common_password` 호출 | `RuntimeError("공통 비밀번호가 없습니다. ... 터미널 입력은 사용하지 않습니다.")` |
| LOGIN-08 | 사이트 접속 자체 불가 | URL 오류/네트워크 차단 | `page.goto(login_url)` | `goto` 단계 예외 → `status="FAILED"` (connection_test_first_user 기준) |
| LOGIN-09 | 계정 중복 제거 확인 | CSV에 동일 `사용자ID`가 여러 행 | `load_first_accounts` 호출 | 먼저 등장한 행만 계정으로 채택, 이후 중복 행은 무시 |
| LOGIN-10 | CSV 첫 계정 한정 로그인 스모크 테스트 | `--limit 1` 동작 | `connection_test_first_user.py` 실행 | `status="CONNECTION_AND_LOGIN_OK"`, exit code 0 |

> 참고: `md/로그인_로직_고정.md`에 따라 로그인 흐름 자체(LOGIN-01~05)는 **고정된 성공 로직**으로 간주하고 수정하지 않는다. 회귀 테스트 목적으로만 재검증한다.

## 3. SESSION — 세션 검증

관련 함수: `login_session_check.check_session`, `wait_for_authenticated_session`

| TC ID | 기능 항목 | 절차 요약 | 기대 결과 |
|---|---|---|---|
| SESSION-01 | 세션 API 정상 응답 | `GET /documents?folderId=...&gubun=D` 호출 | HTTP status 200~299 |
| SESSION-02 | folderId 미지정 시 기본값 사용 | `folder_id=None`으로 호출 | `config["session_check_folder_id"]`가 자동 사용됨 |
| SESSION-03 | 세션 비정상(경로 이동은 성공, 세션 무효) | 폴더 이동 성공 후 세션 재확인 시 4xx/5xx | `status="NAVIGATION_OK_SESSION_INVALID"` (`login_one` 기준) |
| SESSION-04 | JSON 파싱 실패 시 텍스트 폴백 | 서버가 JSON이 아닌 본문 반환 | 예외 없이 텍스트 그대로 `payload`에 담김 |
| SESSION-05 | 세션+네비게이션 모두 정상 | 로그인→폴더 이동→세션 확인 전 과정 | `status="SESSION_AND_NAVIGATION_OK"` |

|---|---|---|---|

## 5. EXPLR — 로컬 파일 탐색 (CSV 기반 + Windows 탐색기 COM)

관련 파일: `HYNIX/explorer_path_test.py`

| TC ID | 기능 항목 | 절차 요약 | 기대 결과 |
|---|---|---|---|
| EXPLR-01 | 정상 사용자 폴더 탐색기로 열기 | `shell.Open(folder)` 호출 | 새 창 또는 기존 창 활성화, exit code 0 |
| EXPLR-02 | 전체 파일 선택 (`--max-select 0`) | `select_files_in_explorer` | `selected_count` = 폴더 내 파일 수 |
| EXPLR-03 | 일부 파일만 선택 (`--max-select N`) | 선택 개수 제한 | `selected_count` ≤ N |
| EXPLR-04 | 이미 열려있는 탐색기 창 재사용 | 동일 폴더 창이 이미 open | `new_window_detected=False` |
| EXPLR-05 | 새 탐색기 창 오픈 | 해당 폴더 창이 없음 | `new_window_detected=True` |
| EXPLR-06 | 사용자 로컬 폴더 없음 | CSV상 경로가 실제 파일시스템에 없음 | `FileNotFoundError("사용자 폴더가 없습니다: ...")` |
| EXPLR-07 | CSV에 없는 사용자ID 지정 | `--user-id` 값이 CSV에 없음 | `ValueError("CSV에서 사용자ID를 찾지 못했습니다: ...")` |
| EXPLR-08 | 부서 경로 빈 값 | CSV `부서 경로` 컬럼 공백 | `ValueError("부서 경로가 비어 있습니다: ...")` |
| EXPLR-09 | 탐색기 창 대기 타임아웃 | `shell.Open` 이후 창이 timeout 내 미출현 | `TimeoutError("Explorer navigation 완료를 기다리다 실패했습니다: ...")` |
| EXPLR-10 | pywin32 미설치 환경 | `.venv`에 `pywin32` 없음 | `RuntimeError("pywin32가 필요합니다. ...")` |
| EXPLR-11 | CSV 기대 파일명과 실제 폴더 불일치 | CSV상 문서가 폴더에 없음 | `missing_files` 목록에 반영 |
| EXPLR-12 | CSV 필수 컬럼 누락 | `부서 경로`/`성명`/`사용자ID`/`문서명`/`확장자` 중 결측 | `ValueError` |

> 환경 제약: 이 항목은 **실제 Windows 데스크톱 세션 + pywin32 COM**이 필요해 헤드리스/서버 환경에서는 실행 불가.

## 6. UPLOAD — 업로드 (생성→청크→완료→가시성 검증)

관련 함수: `create_upload`, `upload_chunks`, `complete_upload`, `upload_file`, `wait_for_uploaded_files` (`login_session_check.py` / `user_upload_test.py`에 중복 구현)

| TC ID | 기능 항목 | 절차 요약 | 기대 결과 |
|---|---|---|---|
| UPLOAD-01 | 업로드 세션 생성 성공 | `POST /document-uploads` (`folderId`,`fileName`,`fileSize`,`mimeType`) | 2xx + body에 `uploadId` 포함 |
| UPLOAD-02 | 업로드 세션 생성 실패 | 잘못된 folderId/서버 오류 | `RuntimeError("upload create failed: status=..., body=...")` |
| UPLOAD-03 | 청크 업로드 성공 | `PUT /document-uploads/{id}/chunks/{index}` 순차 전송 (기본 5MB 단위) | 각 청크 2xx |
| UPLOAD-04 | 청크 업로드 실패 | 특정 인덱스에서 서버 오류 | `RuntimeError("chunk upload failed: file=..., index=..., status=...")` |
| UPLOAD-05 | 업로드 완료 처리 성공 | `POST /document-uploads/{id}/complete` | 2xx |
| UPLOAD-06 | 업로드 완료 처리 실패 | complete 호출 시 서버 오류 | `RuntimeError("upload complete failed: file=..., status=...")` |
| UPLOAD-07 | 업로드 후 가시성 검증 성공 | `wait_for_uploaded_files` 폴링 | `status="UPLOAD_VISIBLE_IN_DOCUMENT_LIST"` |
| UPLOAD-08 | 업로드 후 가시성 검증 타임아웃 | 문서함 목록에 신규 파일명이 timeout 내 미반영 | `status="UPLOAD_VISIBILITY_TIMEOUT"`, `missing_files` 포함 |
| UPLOAD-09 | Dry-run 모드 (기본 동작) | `--execute` 미지정 | 실제 업로드 없이 `status="DRY_RUN_READY"` |
| UPLOAD-10 | 신규 파일 전체 업로드 성공 | `--execute` 지정, 문서함에 없는 파일들 | `status="UPLOAD_COMPLETED"` |
| UPLOAD-11 | 업로드 대상 없음 (전부 이미 존재) | 로컬 파일 전부가 문서함에 이미 있음 | `status="NO_UPLOAD_TARGETS"` |
| UPLOAD-12 | 업로드 검증 미완료 | 업로드는 성공했으나 목록 반영 지연 | `status="UPLOAD_VERIFY_INCOMPLETE"` |
| UPLOAD-13 | 중복 파일 존재 시 차단 (설계상 미검증 상태 — 하단 참고) | 로컬 파일이 문서함에 이미 존재 + 차단 옵션 활성 | `status="BLOCKED_DUPLICATE_FILES"` |

> **알려진 이슈 (버그성 동작, 문서화만 하고 코드는 임의 수정하지 않음)**: `user_upload_test.py`의 `--skip-duplicates`는 `action="store_true", default=True`로 정의되어 있어 **플래그 유무와 무관하게 항상 `True`**로 평가된다. 즉 현재 CLI로는 `UPLOAD-13`(중복 차단) 시나리오에 도달할 방법이 없다. 회귀 테스트 시 이 사실을 전제하고 검증해야 한다.

## 7. VERIFY — 업로드 결과 검증/리포트 (Main_Report.py)

관련 파일: `hynix_interface/Main_Report.py`

| TC ID | 기능 항목 | 절차 요약 | 기대 결과 |
|---|---|---|---|
| VERIFY-01 | 전체 계정 배치 검증 정상 | 로컬 파일 목록 vs 웹 문서함 목록 비교 | 전 계정 `status="VERIFY_OK"`, exit code 0 |
| VERIFY-02 | 특정 사용자만 검증 | `--user-id` 지정 | 해당 계정만 처리 |

## 14. 공통 참고사항

- **공통 실패 패턴**: 대부분의 드라이버(`PROBE-*` 제외)는 최상위 `try/except Exception`으로 감싸 `status="FAILED"` + `message=str(exc)`를 리포트에 남기고 비정상 종료 코드(1)를 반환한다.
- **공통 산출물**: 각 실행은 `reports/{스크립트명}_report.json`(결과), `reports/{스크립트명}.log`(진행 로그), 필요 시 `reports/*.png`(스크린샷)를 남긴다.
- **환경 제약**: `EXPLR-*` 항목은 실제 Windows 데스크톱 세션 + `pywin32` COM이 필요해 헤드리스 서버에서는 실행 불가하다.
- **비밀번호 처리 원칙**: 모든 계정은 공통 비밀번호를 사용하며, 터미널 프롬프트 입력을 의도적으로 배제하고 `DOCSPHERE_PASSWORD` 환경변수 또는 `config/password.txt` 파일로만 제공한다 (`LOGIN-07` 참고).
- **소스 중복 현황(기록용)**: `create_upload`/`upload_chunks`/`complete_upload`/`wait_for_uploaded_files`가 `login_session_check.py`와 `user_upload_test.py`에 중복 구현되어 있다. 두 파일 각각의 UPLOAD-* 케이스를 실행할 때 로직이 갈라지지 않았는지 함께 확인한다.
