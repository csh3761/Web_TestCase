# 태그 이동 로직 검증 기록

## 요약

로그인 성공 후 업로드 대상 leaf 폴더의 `folderId`를 확정하는 공통 이동 로직을 검증했다.
초기 접속 시 사이드바가 접혀 있을 수 있으므로, 문서함 표시명 텍스트를 직접 찾는 방식은 사용하지 않는다.
대신 UI 구조 selector와 CSV/folder_map 기준을 조합한다.

## 현재 이동 로직

```text
로그인 성공
  -> /api/v1/auth/login POST 200 확인
  -> 앱 내부 /api/v1/* request의 Authorization header 캡처
  -> 캡처된 Authorization으로 API 세션 준비 확인
  -> aside.explorer-sidebar 표시 여부 확인
  -> 접혀 있으면 좌측 rail hover
  -> sidebar pin 버튼이 aria-pressed=false이면 클릭해 고정
  -> explorer-workbox-nav__item 구조 selector로 문서함 nav 선택
  -> 부서업무함 루트 row의 상위 li[role='treeitem']와 chevron aria-expanded 확인
  -> aria-expanded=true이면 유지, false이면 chevron 클릭
  -> upload_folder_path_map 기준 문서함명1 > 문서함명2 순서로 진입
  -> leaf row의 data-tree-key에서 실제 업로드 folderId 확정
  -> GET /documents?folderId={folderId}&gubun=D 검증
```

## 기준 selector

| 목적 | selector |
|---|---|
| 사이드바 패널 | `aside.explorer-sidebar` |
| 사이드바 고정 버튼 | `button.explorer-sidebar__pin` |
| 문서함 nav | `button.explorer-workbox-nav__item:has(svg.lucide-building2)` |
| 트리 펼침 | `button.explorer-tree__chevron[aria-expanded]` |
| 선택 row | `.explorer-tree__row.is-selected[data-tree-key]` |

## 확정 규칙

| 규칙 | 설명 |
|---|---|
| 표시명 의존 제거 | `재무회계팀`, `부서문서함` 같은 표시 텍스트 클릭은 핵심 기준으로 사용하지 않음 |
| 구조 selector 우선 | class, icon class, aria 상태값을 기준으로 공통 동작 처리 |
| 펼침 상태 기준 | `aria-expanded=true`는 열림, `aria-expanded=false`는 닫힘으로 판단 |
| folder_map 우선 | 업로드 대상 최종 `folderId`는 CSV 부서경로와 `folder_map` 매핑으로 확정 |
| upload_folder_path_map 우선 | 계정/부서별 하위 문서함 경로를 설정에서 관리 |
| data-tree-key 우선 | 하위 2단계 leaf 폴더의 실제 `folderId` 추출에 사용 |

## 참고 사항

로그아웃 버튼 selector는 아직 확정하지 않았다.
현재 검증 범위는 로그인, 사이드바 진입, 업로드 대상 folderId 확정, 세션 API 확인까지다.
다음 업로드 단계에서는 브라우저 context 종료 방식으로 세션을 정리해도 된다.
