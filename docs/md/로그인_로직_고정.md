# 로그인 로직 고정 기록

## 요약

현재 `src/login_session_check.py` 기준으로 사용자 2명 자동 로그인에 성공했다.
따라서 로그인 로직은 **완성된 기능(fixed feature)** 으로 간주하며, 이후 구현 과정에서 수정하지 않는다.

이 문서는 성공한 로직을 기록하기 위한 문서이며, 앞으로 참고 시 **수정 대상이 아니라 유지 기준**으로 사용한다.

## 성공 결과

| 항목 | 결과 |
|---|---|
| 기준 실행 파일 | `src/login_session_check.py` |
| 기준 문서 | `csv/업로드목록.csv` |
| 비밀번호 방식 | `config/password.txt` 공통 비밀번호 |
| 테스트 계정 수 | 2명 |
| 결과 | 로그인 성공 |
| 기능 상태 | 고정 |

## 고정된 로그인 흐름

```text
업로드목록.csv 읽기
  ↓
첫 2개 고유 사용자ID 추출
  ↓
config/password.txt에서 공통 비밀번호 로드
  ↓
Playwright 브라우저 실행
  ↓
로그인 페이지 접속
  ↓
사용자ID 입력
  ↓
공통 비밀번호 입력
  ↓
로그인 버튼 클릭
  ↓
세션 검증 API 호출
  ↓
성공 여부 기록
```

## 유지 규칙

| 규칙 | 내용 |
|---|---|
| 로그인 로직 수정 금지 | 현재 성공한 흐름은 변경하지 않는다. |
| 비밀번호 입력 방식 유지 | 터미널 입력 대신 `config/password.txt`를 사용한다. |
| 기준 문서 유지 | 사용자 추출 기준은 `csv/업로드목록.csv`이다. |
| Playwright 유지 | 브라우저 로그인 처리는 Playwright 기준으로 유지한다. |
| 후속 기능 분리 | 태그 이동, 업로드, 검증 기능은 별도 모듈로 추가한다. |

## 다음 구현 후보

다음 단계는 로그인 이후 웹 화면에서 특정 위치로 이동하는 기능이다.
사용자가 태그 또는 식별자를 알려주면 해당 대상을 선택해 이동하는 구조를 검토한다.

```text
로그인 성공
  ↓
태그/라벨/텍스트/selector 입력
  ↓
해당 요소 탐색
  ↓
요소 클릭 또는 경로 이동
  ↓
이동 성공 여부 확인
```

## 태그 기반 이동 방식 후보

| 방식 | 설명 | 우선순위 |
|---|---|---:|
| `data-testid` | 프론트엔드 테스트용 태그가 있으면 가장 안정적 | 1 |
| ARIA role/name | 버튼, 링크, 트리 항목 등 접근성 이름 기준 선택 | 2 |
| 표시 텍스트 | 화면에 보이는 부서명/문서함명 기준 클릭 | 3 |
| CSS selector | 클래스, id, DOM 구조 기준 선택 | 4 |
| XPath | 복잡한 구조에서 보조적으로 사용 | 5 |
| API folderId | 화면 클릭 없이 API 경로로 이동/조회 | 별도 우선 검토 |

## 구현 전략

태그 이동 기능은 로그인 로직을 건드리지 않고 별도 함수로 추가한다.
우선은 `data-testid`, `role`, `text` 순서로 탐색하는 공통 이동 함수(navigation helper)를 만들고, 실패 시 어떤 태그를 찾지 못했는지 로그로 남긴다.
