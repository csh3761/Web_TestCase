## 6. apitest: 순수 API 테스트 (현재 방향)

| 명령 | 기능 | 주요 옵션 |
| --- | --- | --- |
| `list` | 시나리오 목록 출력 | 없음 |
| `smoke` | 기능 점검: 로그인, me, 폴더/문서 조회 | `--with-upload` + `--folder-id` 로 업로드 세션 생성, 상태 조회, 취소까지 |
| `login` | 동시 로그인, 세션 유지, 본인 확인 | `--users`, `--iterations`, `--relogin` (로그인 API 부하), `--ramp-up` |
| `upload` | 청크 업로드 5개 API 동시 접근, 부하 | `--folder-id`, `--execute` (필수), `--chunk-concurrency`, `--file-concurrency`, `--source` |

실행: `.venv\Scripts\python.exe -m apitest` 뒤에 명령을 붙입니다.

공통 옵션: `--users` (가상 유저 수), `--iterations`, `--duration`, `--ramp-up`, `--base-url`, `--header NAME=VALUE`, `--report`

모의 서버 (프레임워크 검증용): `python -m apitest.mock.skmr_mock --port 8099`

## 7. skmr 청크 업로드 API (5개)

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| POST | `/api/v1/document-uploads` | 청크 업로드 세션 생성 |
| PUT | `/api/v1/document-uploads/uploadId/chunks/chunkIndex` | 청크 업로드 |
| GET | `/api/v1/document-uploads/uploadId` | 청크 업로드 진행 상태 조회 |
| POST | `/api/v1/document-uploads/uploadId/complete` | 청크 조립 및 문서 등록 |
| DELETE | `/api/v1/document-uploads/uploadId` | 청크 업로드 취소 |

경로의 uploadId, chunkIndex 는 실제 요청 시 값으로 치환되는 경로 변수입니다.

## 9. apitest 검증 상태

| 항목 | 상태 |
| --- | --- |
| 순수 API 로그인 (challenge, RSA-OAEP + AES-GCM) | 실서버 검증됨 (3계정 동시, 세션 섞임 없음) |

| 업로드 대상 folderId | 목록의 folderId 값 사용 (예: DOCBOXM_...), 화면용 id 와 다름 |
| 문서 목록 items 필드 | 미확인 (대상 폴더가 비어 있음) |
