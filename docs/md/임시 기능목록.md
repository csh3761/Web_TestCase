# 임시 기능목록

## 요약

본 문서는 사용자별 문서 업로드 자동화 구현을 위한 **임시 기능목록(feature backlog)** 이다.
실행 기준 데이터는 `C:\Dummy\csv\업로드목록.csv` 하나로 고정한다.
앞으로 자동화 문맥에서 "문서"라고 말하면 이 CSV 문서를 의미한다.

`부서별요약.csv`는 실행에 필요하지 않으므로 제거했으며, 자동화 로직은 `업로드목록.csv`의 행(row)을 기준으로 동작한다.

## CSV 컬럼 구조

| 컬럼 | 의미 | 사용 방식 |
|---|---|---|
| `No.` | 순번 | 처리 순서 및 로그 기준 |
| `부서 경로` | 전체 부서 딥스 경로 | `>` 기준으로 분리해 로컬 경로와 웹 위치 매핑에 사용 |
| `성명` | 사용자명 | 로그 및 검증 보조값 |
| `사용자ID` | 로그인 ID 및 로컬 ID 폴더명 | 사용자별 실행 단위의 기본 key |
| `문서명` | 파일명 본문 | `확장자`와 결합해 업로드 파일명 구성 |
| `문서 종류` | `문서` 또는 `이미지` | MIME type 및 분류 보조값 |
| `확장자` | 파일 확장자 | 파일명, MIME type, 업로드 요청 payload에 사용 |

## 핵심 실행 로직

```text
업로드목록.csv 읽기
  ↓
사용자ID 기준으로 행 그룹핑
  ↓
각 행의 부서 경로 + 사용자ID + 문서명.확장자로 로컬 파일 경로 계산
  ↓
해당 사용자 ID로 로그인 또는 세션 쿠키 적용
  ↓
부서 경로를 기준으로 웹 업로드 대상 folderId 확인
  ↓
문서 업로드 API 실행
  ↓
업로드 완료 검증
  ↓
결과 로그 기록
  ↓
로그아웃
  ↓
다음 사용자ID 반복
```

## 로컬 파일 경로 계산

`부서 경로` 컬럼에는 전체 부서 딥스가 들어있다.
이 값은 `>` 기준으로 분리하고, 로컬 기준 루트와 결합한다.

```text
C:\Dummy
+ 부서 경로
+ 사용자ID
+ 문서명.확장자
```

예시:

```text
CSV:
부서 경로 = 인피니 솔루션 > 경영지원 본부 > 경영기획실 > 재무 회계팀
사용자ID = INF76713
문서명 = 임시자금수지표
확장자 = pdf

로컬 파일:
C:\Dummy\인피니 솔루션\경영지원 본부\경영기획실\재무 회계팀\INF76713\임시자금수지표.pdf
```

## 주의사항

| 항목 | 내용 | 처리 방향 |
|---|---|---|
| 파일명 특수문자 | `A/B테스트결과보고서`처럼 `/`가 포함된 문서명이 있음 | Windows 금지 문자 처리 규칙을 적용해 실제 파일명과 매칭 |
| 중복 파일명 | 동일 사용자 기준 중복 0건 | 자동 순번 부여 금지 |
| 실행 기준 | `업로드목록.csv` 단일 파일 | `부서별요약.csv` 사용 안 함 |
| 경로 기준 | CSV의 `부서 경로` 전체 딥스 사용 | 하드코딩 금지 |
| 비밀번호 | 모든 사용자 계정은 하나의 공통 비밀번호 사용 | 코드 저장 금지, 환경변수 또는 입력값으로 처리 |

## 1. 로그인/로그아웃 기능

| 기능 | 설명 | 고려 사항 |
|---|---|---|
| 사용자별 로그인 | `사용자ID` 기준으로 로그인 | 암호화 로그인 구조가 있으므로 쿠키 세션 재사용 또는 Playwright 로그인 고려 |
| 세션 유지 | 로그인 후 API 호출 동안 쿠키(cookie) 유지 | 세션 만료 시간 확인 필요 |
| 로그아웃 | 사용자별 업로드 완료 후 로그아웃 | 다음 사용자 세션 충돌 방지 |
| 로그인 실패 처리 | 실패 시 해당 사용자 작업 중단 후 로그 기록 | 재시도 횟수 제한 |
| 1차 초안 | CSV에서 첫 2개 고유 사용자ID를 읽어 자동 로그인 후 세션 조회 | `src\login_session_check.py` |

## 3. 웹 업로드 기능

| 기능 | 설명 | 확인된 API |
|---|---|---|
| 업로드 세션 생성 | 파일명, 크기, MIME type으로 업로드 생성 | `POST /document-uploads` |
| Chunk 업로드 | 파일 bytes를 chunk 단위로 전송 | `PUT /document-uploads/{uploadId}/chunks/{index}` |
| 업로드 완료 | 서버에 업로드 완료 처리 | `POST /document-uploads/{uploadId}/complete` |
| 문서 목록 조회 | 업로드 성공 여부 확인 | `GET /documents?folderId={folderId}&gubun=D` |

## 실행 모드 후보

| 모드 | 설명 |
|---|---|
| `check` | CSV 기준 로컬 파일 경로 계산 및 매칭 확인 |
| `dry-run` | 업로드 없이 사용자 그룹, 파일 목록, folderId 매핑만 확인 |
| `run` | 실제 업로드 실행 |
| `retry-failed` | 실패 로그 기준 재시도 |
| `single-user` | 특정 사용자 ID만 테스트 |
| `limit` | 지정 개수만 소량 테스트 |

## 구현 전략

1. `업로드목록.csv`만 기준 데이터로 사용한다.
2. CSV를 읽고 `사용자ID` 기준으로 작업을 그룹핑한다.
3. 각 행의 `부서 경로 + 사용자ID + 문서명.확장자`로 로컬 파일 경로를 계산한다.
4. 파일명 금지 문자는 기존 더미 문서 생성 규칙과 동일하게 보정한다.
5. 사용자별 로그인/세션 적용 후 해당 부서 `folderId`에 업로드한다.
6. `complete` 응답과 문서 목록 조회로 업로드 성공을 검증한다.
7. 결과 로그를 CSV/JSON으로 남기고 실패 항목만 재처리할 수 있게 한다.
