1. 웹사이트 API 직접 호출
   - 가장 빠르고 안정적입니다.
   - 웹사이트가 업로드 API를 제공하거나, 브라우저 개발자도구에서 업로드 요청 구조를 확인할 수 있을 때 가능.
   - 장점: 속도 빠름, UI 변경 영향 적음.
   - 단점: 인증 토큰, CSRF, 세션 처리, 업로드 규격 분석 필요.

2. Playwright / Selenium 브라우저 자동화
   - 실제 사용자가 하는 것처럼 로그인하고, 경로 이동하고, 파일을 업로드합니다.
   - 드래그 앤 드랍 UI도 자동화 가능하고, <input type="file">이 숨겨져 있으면 그 요소에 직접 파일을 넣는 방식도 가능.
   - 장점: 구현 난이도와 안정성의 균형이 좋음.
   - 단점: 웹사이트 UI가 바뀌면 수정 필요.

3. RPA 도구 사용
   - 예: Power Automate Desktop, UiPath 등.
   - 코딩을 최소화하고 화면 클릭/드래그 기반으로 만들 수 있습니다.
   - 장점: 비개발자가 관리하기 쉬움.
   - 단점: 445개 문서 규모에서는 예외 처리, 재시도, 로그 관리가 Playwright보다 약할 수 있음.
4. 반자동 업로드 도우미
   - 엑셀을 읽어서 “다음 업로드 대상”을 보여주고, 사용자가 확인하면 자동 업로드.
   - 로그인/권한/사이트 오류가 자주 나는 환경이면 현실적인 대안입니다.
   - 장점: 사고 위험 낮음.
   - 단점: 완전 자동은 아님.

추천 자동화 루틴
1. 엑셀 파일 읽기
   - 부서 1~4딥스 경로
   - 사용자 ID / 사용자명
   - 업로드 대상 문서 목록
   - 로컬 실제 파일 경로
   - 웹사이트 내 업로드 위치

2. 사전 검증
   - 엑셀에 적힌 파일이 실제로 존재하는지 확인
   - 중복 문서 여부 확인
   - 사용자 ID 폴더와 문서 개수 매칭
   - 누락/오타/확장자 오류 리포트 생성

3. 브라우저 자동 로그인
   - Playwright로 사이트 접속
   - ID/PW 입력 또는 SSO 로그인 대기
   - 로그인 세션 저장 가능하면 다음 실행부터 재사용

4. 엑셀 한 줄씩 처리
   - 부서 경로로 이동
   - 사용자 ID 위치로 이동 또는 생성
   - 해당 문서 업로드
   - 업로드 완료 메시지/파일명 표시 확인

5. 결과 기록
   - 성공 / 실패 / 스킵 / 재시도 필요
   - 실패 사유
   - 처리 시간
   - 업로드된 파일명
   - 결과를 새 엑셀 또는 CSV로 저장

6. 재실행 가능하게 만들기
   - 이미 성공한 항목은 건너뛰기
   - 실패 항목만 다시 실행 가능
   - 중간에 브라우저가 꺼져도 이어서 실행 가능
